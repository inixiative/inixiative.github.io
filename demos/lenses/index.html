Recorded engine responses, with readable JSON and real execution results. Synthetic-fact inference uses a prepared AI example. Each video stands on its own.

  1. 01 / LENSES

    Define the data boundary

    A lens describes the fields and records a query can use. Narrow it, bind an identity, and follow a nested predicate into a database query. Try to cross the boundary and see validation reject it.

  2. 02 / PERMISSIONS

    Decide who receives it

    A permission policy decides who can receive a lens. Combine attributes, roles, and relationships in JSON. Change access upstream and watch the available lenses and query results change.

  3. 03 / SYNTHETIC FACTS

    Make an interpretation queryable

    Infer something the original fields don’t say. Represent it as a typed fact with evidence, connect it through a bridge, and write one predicate across source records and derived interpretations.

A stale answer has lost its basis

When an upstream lens, source query, or permission removes information an answer relied on, that answer must be checked again. Staleness describes a changed dependency. It is separate from how old the information is or when a temporary fact expires.
